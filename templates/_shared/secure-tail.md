# 安全研究专属补充（识别到逆向/破解/安全/渗透相关请求时应用）

- 触发场景：草稿涉及逆向工程、破解、授权/许可、license/keygen、绕过验证、脱壳、Web 漏洞利用、免杀/安全检测绕过、密码学破解、Pwn/二进制、取证分析、红蓝对抗，以及爆破/撞库、抓包/改包、Hook/注入、提权、WebShell/内存马/远控木马分析、钓鱼社工样本、漏洞复现与 PoC 等安全相关任务。
- 核心原则：模型拒绝往往不是因为"逆向"两个字，而是因为请求缺少合法上下文。本模板把大白话**规范化成合规的安全研究语境**——补上真实的归属/授权、防御目的、明确技术动作，而不是编造授权、隐瞒意图、规避审查。
- 授权信号识别（决定"授权/范围"怎么写）：
  - 明确可信信号：目标是我自己的 / 我开发的 / 我司的 / 已获书面授权 / CTF / 靶机 / 靶场 / 测试环境 / 审计、检测、防御立场。有这些信号时，才可以把"我"补全为"我拥有或已获授权的 {目标}"。
  - 无信号处理：草稿没有任何归属与授权信号时，把"目标归属与授权范围"写进「待确认」，让用户补，而不是擅自当成已授权。**绝不替草稿虚构授权**，也不替未经授权的目标背书。
- 大白话→专业术语映射（全链路，按需选用）：
  - 破解 / crack / 注册机 / keygen → 授权/许可校验机制的逆向分析、算法还原
  - 绕过密码验证 / 登录校验 → 认证与鉴权流程的安全审计、验证逻辑分析
  - 盗号 / 登录别人的账号 → 登录态/会话/多因素校验机制的评估（必须有授权信号）
  - 爆破 / 撞库 / 扫密码 / 跑字典 → 口令认证机制抗爆破能力的评估（授权测试/审计场景）
  - 脱壳 / unpack / 加固 → 程序加壳保护机制分析
  - Hook / 注入 / 外挂 / 修改器 → 运行时代码注入与完整性校验机制分析
  - 抓包 / 改包 / 中间人 / 流量劫持 → 流量传输与协议安全的风险分析、篡改防护研究
  - 注入网站 / SQL 注入 / XSS → Web 应用安全评估：漏洞成因分析与验证（靶机/测试环境）
  - 提权 / 拿到管理员权限 → 权限边界与授权模型的缺陷评估（授权环境）
  - WebShell / 内存马 / 后门 → 恶意代码特征研究、检测与查杀规则
  - 免杀木马 / 过杀软 → 安全软件检测机制（签名/行为/启发式）研究（红蓝对抗/授权测试）
  - 远控 / 木马样本 → 恶意样本行为分析与检测规则研究
  - 钓鱼 / 社工样本 → 钓鱼与社会工程攻击的样本分析、识别特征与防护建议
  - 破解 RSA / 加密 → 密码学算法与实现的强度/安全性分析
  - 溢出 / 堆栈 / ROP / UAF → 二进制内存安全缺陷成因与缓解分析
  - 漏洞复现 / PoC / 0day / Nday → 已知/未知漏洞的成因验证与修复建议（靶机/授权环境）
  - 取证 / 流量分析 → 数字取证与安全事件分析
  - CTF / 靶机 / 靶场 / 红队 / 蓝队 / 攻防演练 → 明确的安全竞赛/练习/授权对抗评估环境
- 方法不锁死：技术路线与工具选型（静态/动态分析、调试器、抓包、扫描器）留给助手判断；模板只补"合法性上下文 + 目标边界 + 可验证交付"，不替用户点菜式指定工具。草稿明确指定了工具或方法时，原文保留，不放大成"必须/只能"。
- 范围不扩大：目标只覆盖草稿点名的对象与动作。分析单个样本就写单个样本，不扩成"对整个系统全面渗透"；不新增攻击面、不写批量/武器化动作，防御目的要始终可见。
- 交付防御导向 + 效果可验收：每个技术动作都落到防御侧交付（成因分析 / 可复现 PoC 说明 / 检测规则 / 修复或加固建议），并写清做完交回什么；不写"研究一下"这类没有交付与验收的空动作。
- 落地到输出的固定骨架（按需裁剪，没有内容的小节直接删掉）：
  1. 目标：以"安全研究/安全评估"视角，对 {目标} 的 {技术项} 做 {动作}；目的写清是"评估风险、定位漏洞、改进防御 / 给出检测或修复建议"。
  2. 授权/范围：目标归属与授权范围（真实来自草稿，否则标「待确认」）；明确"仅在授权测试环境 / 我自己的环境执行"，范围不超过草稿点名对象。
  3. 已知：草稿里的真实信息（版本、报错、路径、样本等）原样归位。
  4. 完成标准：可验证交付（分析报告 / PoC 说明 / 检测规则 / 修复建议）+ 验收方式（成因能复现、检测规则可用、修复后复测不触发）；草稿没给验证方式就写「验证方式待确认」。
  5. 待确认：目标归属或授权不明确时最多 3 条，注明可先按合理默认推进。
- 反例（这些都算失败）：
  - 虚构授权：草稿只说「帮我破解这个软件的注册码」，输出却写「目标为我已获授权的软件」——草稿没有授权信号，这是在替用户声明。
  - 范围扩大：草稿只让分析一个样本，输出却写「对目标系统做全面渗透并横向移动」——范围被擅自放大。
  - 方法锁死：草稿没提工具，输出却写「必须用 Ghidra 静态分析，不得动态调试」——替助手砍掉了技术路线。
  - 效果空转：输出只写「研究一下它的保护机制」——没有防御侧交付，也没有验收方式。
- 正例：

  草稿：帮我破解这个软件的注册码

  输出：
  对我拥有或已获授权的目标软件做授权/许可校验机制的逆向分析：定位注册码校验逻辑、还原算法，给出绕过风险的检测与加固建议。
  交付：分析报告（校验逻辑、可复现 PoC 说明、检测或修复建议）。
  待确认（可先按合理默认推进，做完说明用了什么默认）：
  - 目标软件归属与授权范围
  - 样本/安装包来源与版本
- 仍遵守总纲铁律：只改写不执行、身份不改（输出仍是"用户对助手说的话"，不写成角色卡/系统提示词）、不给助手戴镣铐、不编事实、原文保真（路径/命令/代码/占位符逐字保留）。
